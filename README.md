# Kompas3D MCP

**MCP-сервер для КОМПАС-3D v24: ИИ-агент строит и проверяет настоящие детали и сборки, а сервер
отвечает тем, что измерил на модели, а не тем, что вызов «прошёл».**

> *English summary.* A Model Context Protocol server that lets an AI agent drive a real, licensed
> KOMPAS-3D v24 (x64) over COM: parts, sketches, features, patterns, booleans, assemblies and mates,
> STEP and image export. Every mutating call reports a measured verification level (volume, bodies,
> faces, re-read parameters, save/reopen), journals operations for idempotent retries, rejects stale
> revisions, and is confined to configured disk roots. No arbitrary code execution. 63 tools,
> MIT licensed. Documentation is in Russian.

шаг сервер подтверждает измерением.

## Что умеет

- **Детали.** Эскизы на базовых и смещённых плоскостях с правкой отдельных сущностей и проверкой
  определённости; выдавливание, вращение, по траектории, по сечениям, оболочка; скругления, фаски,
  родные отверстия; булевы операции, разделение и отсечение плоскостью, перенос и поворот тела;
  массивы по сетке, круговые и зеркальные.
- **Правка, а не пересоздание.** Параметры существующего признака читаются и меняются на месте;
  признак можно подавить, восстановить или удалить; опорную плоскость эскиза можно сменить.
- **Вспомогательная геометрия.** Плоскости, оси и точки создаются как объекты модели и правятся.
- **Сборки и сопряжения.** Вставка и замена компонентов, размещение, проверка ссылок на файлы;
  создание, параметры, фиксация и удаление сопряжений.
- **Измерение и топология.** Габарит, объём, площадь, центр масс; грани и рёбра конечного тела и
  однозначный выбор по структурному признаку.
- **Обмен.** Экспорт и импорт STEP; растровый снимок модели (PNG, JPG, BMP, TIF) в заданной
  проекции (`view`: спереди, сверху, изометрия и др.), который возвращается клиенту картинкой.
- **Сеанс.** Подключение к КОМПАС или запуск своего экземпляра, явный захват и передача сеанса
  между чатами без перезапуска клиента.

## Почему ему можно доверять модель

- **Измеренный уровень проверки.** В ответе каждой операции есть `verification.level`: от
  `call_returned` («КОМПАС сказал, что получилось») до `geometry_checked` (модель перечитана, тела,
  габарит и объём совпали) и `geometry_roundtrip_checked`. Сервер не сообщает уровень, которого не
  достиг; непроверенное перечислено в `unverified_aspects`.
- **Журнал операций и идемпотентность.** Каждая мутация несёт `operation_id` и пишется в журнал до
  и после выполнения. Повтор с тем же `operation_id` не применяет операцию второй раз, а тот же
  `operation_id` с другими аргументами отвергается (`OPERATION_ID_CONFLICT`). Ошибка говорит,
  можно ли повторять и как (`retry_policy`), и были ли частичные эффекты.
- **Защита от устаревшего состояния.** `expected_revision` отвергает мутацию, если модель
  изменилась с момента чтения (`REVISION_CONFLICT`); ссылки на грани, рёбра и признаки привязаны к
  ревизии и устаревают явно (`STALE_REFERENCE`), а не указывают на чужой объект.
- **Политика путей.** Сервер читает и пишет только в корнях из конфигурации (только чтение, запись,
  экспорт). Путь вне них отклоняется (`PATH_NOT_ALLOWED`) до обращения к КОМПАС.
- **Изоляция COM.** Host говорит MCP и не трогает COM вообще; весь КОМПАС живёт в отдельном
  процессе Worker с одним STA-потоком. Host следит за Worker, перезапускает его при сбое и прямо
  сообщает, что прежние `document_id` после перезапуска недействительны.
- **Никакого произвольного кода.** Нет инструмента «выполни скрипт» или «вызови COM-метод по
  имени»: только типизированные инструменты со строгими JSON-схемами аргументов.
- **Только документированный API.** Каждая операция идёт маршрутом из официальной справки
  КОМПАС v24; сверка вызовов со справкой лежит в [`docs/API_COMPLIANCE.md`](docs/API_COMPLIANCE.md).
- **Пользовательский КОМПАС не закрывается.** Сервер завершает только тот экземпляр, который
  запустил сам.

## Как устроено

```
MCP-клиент (stdio)
   │
KompasMcp.Host        контракты, валидация по схемам, журнал, реестр ссылок и ревизий; без COM
   │ именованный канал
KompasMcp.Worker      отдельный процесс, один STA-поток с циклом сообщений; здесь живёт КОМПАС
   │
KompasMcp.Api5Adapter единственный проект, который знает типы КОМПАС (API5 и точечно API7)
```

Решения по архитектуре: [`docs/adr/`](docs/adr/).

## Требования

- Windows x64.
- Установленный и лицензированный **КОМПАС-3D v24 x64**. Сервер работает с настоящим приложением
  и CAD не эмулирует.
- Для сборки: .NET SDK 10 (`global.json` закрепляет 10.0.401). Для запуска поставки: .NET 10
  Desktop Runtime x64.

Interop-сборки берутся из каталога установки КОМПАС и в репозиторий не входят. По той же причине
сборка в облачном CI невозможна: проверка изменений идёт на машине с установленным КОМПАС.

## Установка и подключение

1. Собрать поставку (каталог `artifacts\publish`):

   ```powershell
   .\scripts\publish.ps1 -Configuration Release
   ```

   Для отладочной сборки: `dotnet build KompasMcp.sln -c Debug -p:Platform=x64 -p:KompasRoot="<корень установки КОМПАС-3D v24>"`.

2. Создать конфигурацию из шаблона и задать корни доступа к диску:

   ```powershell
   Copy-Item config\kompas-mcp.example.json config\kompas-mcp.local.json
   ```

3. Подключить сервер в MCP-клиенте как stdio-сервер:

   ```json
   {
     "mcpServers": {
       "kompas": {
         "command": "<каталог-поставки>\\KompasMcp.Host.exe",
         "args": ["--config", "<путь>\\kompas-mcp.local.json"],
         "timeout": 600000
       }
     }
   }
   ```

4. Проверить из клиента: `kompas_capabilities`, `kompas_health`, затем
   `kompas_connect {"mode": "launch"}`.

Подробно: [установка](docs/operator-guide/install.md), [конфигурация и клиент](docs/operator-guide/mcp-config.md),
[сборка](docs/operator-guide/build.md), [диагностика](docs/operator-guide/diagnostics.md).
Модульные тесты идут без КОМПАС:
`dotnet test tests\Unit\KompasMcp.Unit\KompasMcp.Unit.csproj -c Debug -p:Platform=x64`.

- `kompas_delete_feature` — **Удалить признак**. Удаляет признак (измерено пробой L.8: ksDocument3D.DeleteObject → true, число признаков минус один).

- `kompas_export_step` — **Экспорт STEP**. Экспорт нативным конвертером.
- `kompas_import_step` — **Импорт STEP**. Чтение STEP.
- `kompas_export_image` — **Снимок модели**. Растровый снимок документированным маршрутом API5: ksDocument3D.RasterFormatParam → ksRasterFormatParam → SaveAsToRasterFormat.
- `kompas_probe_units` — **Замер единиц**. Строит известную геометрию и возвращает сырые показания всех измерительных вызовов.
- `kompas_read_topology` — **Топология тела**. Грани и рёбра из конечного тела (GetMainBody→FaceCollection→EdgeCollection), а не из EntityCollection: коллекция рёбер модели содержит эскизные и служебные контуры.

- `kompas_update_plane` — **Изменить плоскость детали**. Меняет УЖЕ СОЗДАННУЮ плоскость детали как объект модели: смещение вдоль нормали, угол наклона, знак направления, опору.

## Состояние и планы

Целевая версия: КОМПАС-3D v24.0.0.2799 x64. Обязательный объём закрывается, только когда каждое
применимое действие режима (создание, чтение, правка, перестроение, сохранение и повторное
открытие, подавление, удаление зависимостей, отрицательные проверки, проверка геометрии)
подтверждено живым прогоном.

| Профиль выпуска | Режимы | Общие зависимости |
|---|---|---|
| Твердотельное моделирование деталей (`mechanical-core-v1`) | 54/54 | 15/15 |
| Сборки (`assemblies-minimal-v1`) | 7/7 | 5/5 |
| Сопряжения (`mates-minimal-v1`) | 6/6 | 5/5 |

Клиентская приёмка поставки рабочим MCP-клиентом пройдена: 16 сценариев из 16. Текущее состояние
и измеренные числа: [`docs/STATUS.md`](docs/STATUS.md); каталог операций, матрица покрытия и
профили: [`coverage/solid-v24/`](coverage/solid-v24/).

![Дашборд прогресса выпуска mechanical-core-v1: готовность 100 %, 54 режима из 54 и 15 зависимостей из 15](docs/assets/dashboard-20260923.png)

**Чего пока нет:**

- **Чертежи и спецификации.** Работы с 2D-документами КОМПАС в сервере пока нет.
- Родные приклеивание и вырезание по траектории (`SM-04.boss`) отложены; сохранение копии базового
  объекта при объединении (`SM-15.union.mode_save_base_copy`) запланировано следующим этапом.
- Каталог операций шире выпуска: 32 семейства, из них 14 в обязательном объёме. План:
  [implementation-plan.md](coverage/solid-v24/implementation-plan.md).
- Сервер не правит произвольную операцию КОМПАС: то, что не подтверждено, возвращается как
  `CAPABILITY_UNAVAILABLE` с объяснением, а не как успех.

## Что не входит в репозиторий

Доказательства прогонов и приёмки, собранные поставки, рабочие данные, модели заказчика и
локальные конфигурации в публикацию не входят. Документы называют их по имени: это указание на
доказательство, которое читатель воспроизводит опубликованными приборами из `scripts/` на своей
установке КОМПАС. Полный перечень и пояснения: [обзор](KOMPAS3D_MCP.md), раздел «Что намеренно не
входит в публичный репозиторий». Набор публикации проверяет страж
[`scripts/verify-publish-set.py`](scripts/verify-publish-set.py).
