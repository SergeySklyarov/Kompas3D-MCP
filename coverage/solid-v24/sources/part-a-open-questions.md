# P6.0 срез A — открытые вопросы

Уровень доказательности среза — документация + метаданные. Всё, что ниже, **не** разрешается
из них и требует адресной пробы (по одному сеансу КОМПАС, последовательно, модели в scratch).
Формат: вопрос → что блокирует → следующий проверяемый шаг.

## Топ-5 по влиянию на архитектуру / целые семейства

### OQ-A9. Можно ли создавать «API7-only» признаки через API5 (`NewEntity(o3d_…) + GetDefinition`)?
- Семьи: SM-10 (618), SM-12.draft_from_edges (644), SM-16.split (633), SM-17.scaling (531), SM-17.reposition (569), SM-06 (673). В `kApi5.tlb` определений нет; типы в `ksConstants3D.tlb` есть. Прецедент SM-07: `NewEntity(o3d_holeOperation)` → `GetDefinition()=null` (P2.1), тогда как API7-маршрут работает.
- Влияние: если ответ «null» — эти семейства реализуемы только через API7-мост (TransferInterface из API5-сеанса, уже работавший в пробе A7.2), и архитектура адаптера фиксирует два слоя API; если «работает» — достаточно API5-очереди.
- Проба: для каждого типа `NewEntity + GetDefinition` и QI результата на соответствующий API7-интерфейс; фиксировать HRESULT/тип/null.

### OQ-A1. Как создаётся базовая кинематическая операция в API7?
- SDK `ievolutions_add.html` допускает только `o3d_bossEvolution/o3d_cutEvolution/o3d_EvolutionSurface`; базовый тип `o3d_baseEvolution=45` существует (TLB) и имеет API5-определение. Семейство SM-04 требует «создание/добавление/вырезание».
- Влияние: весь SM-04.base: либо единственный корень — API5 NewEntity(45), либо `IModelContainer.AddObject(45)`.
- Проба: оба вызова на независимых моделях; критерий — ненулевой IEvolution/ksBaseEvolutionDefinition + валидное тело (V=профиль×путь).

### OQ-A18. Как задать и прочитать набор сохраняемых тел при «Разрезать» (SM-16.split)?
- `ISplitSolid` объявляет только `CutObjects`. UI выбирает части постфактум (`cm_choice_of_bodies.html`: «Изменение набора тел», исключённые тела скрыты, но остаются в файле). Без управления составом результат «несколько тел» нельзя ни воспроизвести, ни отредактировать (docs/05 §4.5).
- Влияние: вся операция split и её lifecycle (edit/read).
- Проба: split бруска плоскостью → изучить коллекцию тел (BodyParts/MultiBodyParts у IModelObject1), Hidden/Excluded у частей; найти, чем API фиксирует «оставленные»; при неудаче — blocked_api с минимальным примером.

### OQ-A3. Есть ли API у «изменения формы сечения» кинематической операции (SM-04)?
- UI: `Изменение формы` по законам/по значениям в точках траектории + «Разбивать на грани» (`section_shape_changes.html`). В `IEvolution`/`ksBaseEvolutionDefinition` — ни одногоrelated-члена.
- Влияние: полнота SM-04 (режимы, требованные docs/05: «ориентация, начальные условия и дополнительные направляющие» частично здесь же); риск ложного «покрыто» при отсутствии.
- Проба: поиск скрытых интерфейсов (QI объекта эволюции на iid’ы `I*Law*`/аналогичные; перебор members через IDispatch GetIDsOfNames по именам из UI-словаря); при нулевом результате — `blocked_api` + композиционная альтернатива (серия эскизов-сечений ≈ loft, с маркировкой `alternative_of`).

### OQ-A7. Работает ли `IModelContainer.PipeElements` живьём (SM-06)?
- Объявлен в `kAPI7.tlb` (dispid 10033, измерено env-passport), интерфейс IPipeElement v24; в prebuilt-обёртке свойства нет — обёртку использовать нельзя (нужен tlbimp от установленного TLB, уже демонстрировалось: scratch/apigen). Живой отклик не проверялся (правило ADR-003: окончательное слово за IDispatch).
- Влияние: всё семейство SM-06 и ответ «родной трубчатый элемент vs sweep-композиция».
- Проба: tlbimp-обёртка (или late-binding) → `PipeElements.Add()` → Diameter=10, WallThickness=2 (режим Диаметр+стенка), траектория — отрезок 100 мм, OperationResult=NewBody; эталон V=π·(5²−3²)·100=5026.5 мм³; перечитать параметры, save→reopen.

## Прочие вопросы (по семействам)

### SM-04
- **OQ-A2** — тело как инструмент вырезания по траектории (`aw2209427.html`): каким членом задаётся (Edges принимает только кривые; возможно BodyCollection/ChooseBodies в API5-сеансе)? Проба: API5 cut-evolution с выбором тела; блокирует режим «вырезание телом».
- **OQ-A4** — тонкая стенка sweep/loft в API7: `IEvolution`/`ILoft` тонкостенных членов не объявляют, API5 `SetThinParam` — да. Подтвердить, что thin-wall маршрут = API5 (иначе блокировать режим в API7-ветке). Проба: SetThinParam → V-дельта тонкой трубы.
- **OQ-A5** — `EvolutionVersion1/2` («Вариант 1/2», версий оптимизации): семантика в справке не раскрыта. Только различающиеся эталонные тела обоснуют отдельный режим в матрице.
- **OQ-A6** — направляющие: API5 `Get/SetDirectionalLine` (одна, эскиз), API7 `ILoft.DirectionalLines` (массив) + `AxisLine`. В API5-определении «по сечениям» нет ни AxisLine, ни couplings. Проба: эквивалентна ли одна directional line в API5; иначе SM-05-couplings = API7-only.

### SM-06
- **OQ-A8** — «Область применения» трубчатого элемента (UI-секция «Тела/Компоненты/…») не отражена в `IPipeElement` (TLB). Проба: pipe Cut на многотельной детали — задевает ли нецелевые тела; нужен ли Choose*-механизм.

### SM-11/SM-10
- **OQ-A10** — значения `StopChamferOffsetMode`: отдельного chamfer-enum нет, есть `ksFilletOffsetModeEnum{ByPersent,ByLength,ByAngle}` (скругление). Проба: перечислить допустимые 0..N на живом IChamfer с проверкой %/мм/° по объёму; без этого enum-поле в схеме инструмента недоказуемо.

### SM-12
- **OQ-A11** — `IIncline.Plane`: принимает ли грань как «Основание» (UI позволяет). Проба: Set Plane=грань → Valid/объём.

### SM-13
- **OQ-A12** — значения `ThinType`/`thinType` (Наружу/Внутрь): собственный enum в `ksConstants3D.tlb` не найден (кандидат `ksDirectionTypeEnum{dtNormal=0,dtReverse=1,...}`). Проба: обе величины на коробке SOL-SHELL — какая сторона растёт.
- **OQ-A13** — `IMultiThicknessGroupsManager` (kAPI7.tlb) содержит точный набор members под переменную толщину оболочек (MultiThick/AddMultiThicknessGroup/Groups…{Arbitrary|Sets}Thicknesses), но не найден путь получения экземпляра из `IShell`/`IModelContainer` (в TLB нет владеющего свойства). Проба: QI объекта shell-признака на iid 4FB26621-…; просмотр Members живым объектом. Блокирует `SM-13.shell.mode_variable_thickness`.

### SM-14
- **OQ-A14** — маппинг UI «Толщина/Симметричная толщина» на API5 `SetThinParam(thinType,normalThickness,reverseThickness)` и роль `IRib.Body`/отсутствие цели в API5. Проба: матрица Side(4)×thinType(2), эталон V треугольного ребра.

### SM-15
- **OQ-A15** — смысл `ksOperationNewBody=1` для булева (UI-кнопка «новое тело»?). Проба: BaseObject+Modify с BooleanType=1, проверка числа/состава тел.
- **OQ-A16** — касание/несвязность: разрешает ли ядро union касательных тел и что делает split по граничному касанию (docs/05 §9.3). Проба: два куба, грань-в-грань; измерение числа тел и предупреждений.
- (Также: уточнить relationship `IBoolean.Bodies` vs `BaseObject/ModifyObjects` — три коллекции в одном интерфейсе; пробой.)

### SM-16
- **OQ-A17** — допустимость секущих «тело» и «грань» в API7 `ICut.CutObjects` (UI-список шире helpstring «эскизы и поверхности»). Проба: сечение гранью/телом → код результата КОМПАС.

### SM-17
- **OQ-A19** — запись положения: `IBodyReposition.Position` только propget (`ILocalCoordinateSystem`). Гипотеза: мутируется возвращённый объект ЛСК (Origin/оси) + `Update()`; «По объекту» — вероятно через `RepositionObjects`/привязку ЛСК. Проба: перенос бруска +10 мм по X, SOL-MOVE-критерии; блокирует оба режима SM-17.reposition.

### Единицы (общий)
- Все `Angle` (chamfer/incline/rib/draft) и двойные размеры — подтвердить единичной пробой (метод `kompas_probe_units` уже в каталоге; для API7 — аналог через измерение объёма). До подтверждения в схемах инструментов значения не «мм/градусы by fiat», а «as-probed».
