# Assemblies - решения и измерения

Модуль: `src/KompasMcp.Api5Adapter/Api5Session.Assembly.cs`. Здесь - история правок, вынесенная из
кода. Действующие правила остались в коде под метками `INVARIANT:` / `DOC:` / `MEASURED:` / `LIMIT:`.

## <a id="insert-route"></a>Маршрут вставки компонента (05.10.2026)

**Что было.** Вставка шла через `ksDocument3D.CreatePartInAssembly`.

**Что измерено.** 05.10.2026 живым прогоном (проба M, `tools/KompasMcp.Api7Probe`, флаг `--mate`):
`CreatePartInAssembly` давал компонент БЕЗ ГЕОМЕТРИИ - 0 тел, 0 граней. Справка
(`ksdDocument3d_createpartinassembly.html`) называет его «деталь СОЗДАВАЕМАЯ в сборке» и «плоскость, к
которой ПРИКЛЕИВАЕТСЯ деталь» - то есть СОЗДАНИЕ новой (пустой) детали, а не вставка существующей.

**Что решено.** Вставка - документированный `IPart7.Parts → IParts7.AddFromFile(FileName,
ExternalFile=true, Redraw=true) → Part7` (`iparts7_addfromfile.html`). На том же прогоне: компонентов
2, у КАЖДОГО тело = 1 и граней 6, геометрия переживает save→close→reopen. Повторная вставка того же
файла - тем же вызовом; отдельный `CopyPart` не нужен.

## <a id="replace-source"></a>Замена источника компонента (04.10.2026)

**Что было.** Замена шла присваиванием API7-свойства `fileName` (`ipart7_filename.html`), и о
результате код молчал.

**Что измерено.** 04.10.2026: одного API7-сеттера НЕ хватало - замена не переживала
save→close→reopen. Документированный `ksPart.SetFileName` (`kspart_setfilename.html`) требует вызова
`ksPart::Update` для вступления изменения в силу.

**Что решено.** Запись - `ksPart.fileName` + `ksPart.Update()`, результат проверяется ЧТЕНИЕМ ОБРАТНО
документированным геттером. Расхождение обёртки и справки названо: справка обещает метод
`BOOL SetFileName`, поставленная обёртка 24.0.0.2799 объявляет только свойство без возврата.

## <a id="replace-partial"></a>«Источник не заменён» - частичный эффект (05.10.2026)

**Что было.** При расхождении перечитанного имени редакция отвечала `RetryPolicy.SameOperationId` без
`partialEffects`, и журнал считал отказ чистым - то есть разрешал повтор ТЕМ ЖЕ `operation_id`.

**Что измерено.** К моменту отказа уже выполнены `ksPart.fileName = …` и `ksPart.Update()`:
перечитанное имя - КОСВЕННЫЙ признак, а не доказательство, что модель не изменилась. Повтор тем же id
применил бы замену ВТОРОЙ раз (находка §5 задания 05.10.2026).

**Что решено.** Отказ объявляется частичным эффектом, ревизия поднимается, повтор требует
согласования.

## <a id="identity"></a>Тождество компонента по номеру (04–05.10.2026)

**Что было.** Адрес компонента - порядковый номер в плоской `ksDocument3D.PartCollection(true)`.
Сверка тождества жила в адаптере, разложенная по ветвям, и отказом управляли три признака (источник,
имя, матрица размещения). Снимок матрицы хранился в ССЫЛКЕ.

**Что измерено.** 04.10.2026: `IPart7.Reference` равен 1073741857 и номером компонента НЕ является;
`GetPart(1)` на сборке с двумя компонентами вернул компонент второго источника, `GetPart(2)` - null.
05.10.2026: снимок матрицы устаревал от СОБСТВЕННОЙ мутации сервера, и вторая мутация по той же
ссылке отвергалась `STALE_REFERENCE` (регрессия п. 1 задания).

**Что решено.** Решение вынесено в ЧИСТУЮ функцию `ComponentIdentity.Decide` (Domain, без COM-типов).
Отказ решает ТОЛЬКО ФАЙЛ-ИСТОЧНИК - единственный измеренный и не изменяемый сам по себе признак; имя
и матрица - ПРИМЕЧАНИЯ. «Сверить нечем» (источник не прочитан) - тоже отказ. Матрица читается СВЕЖЕЙ
у живого родителя (`Parent7`), а не снимком из ссылки.

## <a id="api7-twin"></a>Двойник `IPart7.Measurement3D` (08.10.2026)

**Что было.** Наряд G1 предписывает маршрут зазора `IPart7.Measurement3D` → `IMeasurement3D`
(справка `ipart7_measurement3d.html`, `imeasurement3d.html`, «Версия Компас v23»).

**Что измерено.** 08.10.2026 двумя приборами. (1) Сканер метаданных: поставленная
`Interop.KompasAPI7.dll` (03.03.2025) объявляет `IPart7` со 154 членами, и `Measurement3D` среди них
НЕТ; `IMeasurement3D` в сборке нет вовсе; `IBody7.CheckIntersectionWithBody`/`Ex` тоже нет.
(2) Сборка, сгенерированная `TlbImp` из установленного `Bin/kAPI7.tlb` (21.04.2025): `IPart7` - 178
членов, `get_Measurement3D` есть; `IMeasurement3D` - IID `f59ff609-45c2-4afb-b3c4-08184b9900ff`,
46 членов. Тот же набор имён найден в самом сервере API7 `Bin\kAPI7.DLL`, то есть сервер полный, а
устарела только .NET-обёртка. Форма расхождения - ДОПИСЫВАНИЕ: 18 методов в конце списка, первые 106
слотов совпадают, поэтому поставленная обёртка не «сдвинута», а неполна.

**Что решено (решение заказчика 08.10.2026).** Маршрут наряда сохраняется: недостающий интерфейс
объявляется в адаптере типизированным `[ComImport]`-двойником (`Api7/Api7InteropTwin.cs`), IID и
раскладка сняты машинно с интеропа, сгенерированного из установленного TLB, в порядке МЕТАДАННЫХ
(для импортированного dual-интерфейса это и есть порядок vtable). `IDispatch` не используется
(ADR-004). Двойник `IPart7` объявлен до `get_Measurement3D` включительно, `IMeasurement3D` - до
`GetMinPoint2`. Прибор получил флаг `--order` и печать атрибутов: без них порядок vtable неоткуда
взять, а `InterfaceType` неоткуда сверить.

## <a id="interference-contracts"></a>Пересечения и зазор: контракты и что измерено (08.10.2026)

**Маршруты.** Пересечения - API5: `ksDocument3D.PartCollection(true)` → `ksPart.BodyCollection` →
`ksBody.CheckIntersectionWithBody` → `ksIntersectionResult.GetCount/GetIntersectionType`; грани -
`ksBody.GetIntersectionFacesWithBody`. Зазор - API7: `IKompasDocument3D.TopPart` →
`IPart7.Measurement3D` → `IMeasurement3D.Object1/Object2` → `Calculate`. Оба маршрута в одной паре не
смешиваются.

**Непрочитанное не равно нулю.** `intersecting` и `volumetric` у пары - `bool?`: NULL ядра это
«пересечений нет» с основанием `kernel_null_documented_as_no_intersection`, а COM-исключение - НЕ
«нет пересечений», а `kernel_call_failed` при `null` в обоих полях. Правило вынесено в ЧИСТУЮ функцию
`InterferenceRules.Decide` (Domain) и держится тестом с отрицательным контролем.

**Измерено живым прогоном 08.10.2026** (группа `--interference-only`, 48 строк, 0 отказов;
`docs/acceptance/interference/interference-acceptance.json`): зазор `dx − 10` при трёх компонентах;
объёмное пересечение `itBody` при `dx = 5`; касание `itTangentSurface` при `dx = 10` только с
`check_tangent = true`; зазор `2,928932` у повёрнутого на 45° компонента; точки отрезка минимального
расстояния `(5, 5, −5)` и `(10, 5, −5)`; 190 пар на 20 кубах за 0,5 с. Единица длины справкой НЕ
названа и остаётся допущением в `units_basis`.

**Названо, а не сглажено.** (1) Код документа-не-сборки у этого блока - `WRONG_DOCUMENT_KIND`, а у
блока C1 в том же положении - `INVALID_ARGUMENT`: расхождение внесено нарядом G1, и оно намеренное,
а не дрейф. (2) `IMeasurement3D.GetMinPoint1/2` возвращают FALSE, когда ближайшие точки НЕ ЕДИНСТВЕННЫ;
в ответе это `null` с причиной, а не подставленные координаты. (3) Компонент без тел в
`check_interference` НЕ роняет весь вызов: его пары получают `basis = component_has_no_body` и
`intersecting = null`, потому что вопрос остался без ответа, а не получил ответ «нет».
