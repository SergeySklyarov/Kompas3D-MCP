# Dismantle - решения и измерения

Модуль: `kompas_set_dismantle`, `kompas_list_dismantle_steps` (наряд `OMEGA_G9_DISMANTLE`). Здесь -
история, отвергнутое и границы, вынесенные из кода; действующие правила остаются в коде под метками
`DOC:` / `MEASURED:` / `INVARIANT:` / `LIMIT:`.

## <a id="probe"></a>Проба записи шага: маршрут, направление и доказательство разнесения (21.10.2026)

**Что было.** Наряд §1 ставил главным риском именно запись шага: «если документированного способа
назначить шагу компоненты И перемещение нет - стоп, BLOCKED». Сняты страницы справки семейства
`IDismantleParameters`/`IDismantleStep` (`reference/kompas-sdk-v24/docs-wire-20261021-dismantle/`,
35 страниц из 36, отрицательный контроль - 404 на два выдуманных имени). Страниц свойств и методов
`IDismantleStep` в зеркале не было; они есть в справке и сняты.

**Что измерено.** Шаг пишется: `QI(IAssemblyDocument → IDismantleParameters)` отвечает,
`AddDismantleStep()` отдаёт `IDismantleStep`, `Parts` принимает массив `IPart7` (один элемент приходит
обратно как `VT_DISPATCH`, два - как `SafeArray`), `Distance` пишется и читается, `Update()` вводит шаг в
модель (до него `DismantleStepsCount` = 0, после - 1). Шаги, расстояние и число компонентов переживают
`Save()` → `close()` → `Open()`; `DismantleMode` после переоткрытия читается `FALSE`.

**Направление.** Документированный вход - только `DirectionObject` (`IModelObject`); `Vector`
(`IVector3D`) объявлен «доступно только для чтения», числового входа нет. Измерено на сборке из двух
компонентов (второй сдвинут на 150 мм по X): `Parts = [компонент 0]`, `Distance = 40`, а
`DirectionObject` по очереди - плоскость XoY, XoZ, YoZ, ребро компонента, грань компонента, сам
компонент → смещение компонента **ноль**; `DirectionObject` = вспомогательная ось сборки
(`IAuxiliaryGeomContainer.Axes3D.Add(o3d_axis2Points)`, точки (0,0,0)-(100,0,0), `Update()` = TRUE) →
смещение ровно `(40, 0, 0)`. Второй шаг на оба компонента с осью по Y и `Distance = 25` даёт
`(0, 25, 0)` обоим; итоговые смещения `(40, 25, 0)` и `(0, 25, 0)` - шаги складываются.

**Что читается обратно.** `DismantleStepsCount`, `DismantleStep[Index]`, `Parts`, `Distance` - читаются.
`DirectionObject` после записи читается `null` при любом кандидате, `Vector` приходит с
`ParametersType = ksVector3DUnknown` и `Parameters = null`: **направление шага чтением не
подтверждается**. Поэтому `kompas_list_dismantle_steps` не может вернуть направление - это названо в
описании инструмента, а не заменено догадкой.

**Чем доказано разнесение.** Документированным чтением положения компонентов
(`IPart7.GetSummMatrix` - тот же маршрут, что у `kompas_list_components`): в разнесённом виде смещение
равно сумме шагов с допуском, названным в коде; при `DismantleMode = FALSE` матрицы возвращаются к
собранным точно. Габарит тела (`ksBody.GetGabarit`) для этого не годится: у компонента он отвечает в
его собственных координатах и одинаков в обоих режимах - измерено.

**Отвергнуто.** (1) Гипотеза «направление можно задать плоскостью или ребром» - опровергнута: смещение
ноль при всех четырёх кандидатах, работает только ось. (2) Гипотеза «`Vector` даст прочитать
направление» - опровергнута: объект приходит без параметров. (3) Порядок записи «направление первым,
затем компоненты и расстояние» - направление так же не сохраняется, на смещение не влияет.
(4) Подтверждение разнесения габаритом сборки - не годится по той же причине, что и габарит тела.

**Остаётся риск.** Ось как `DirectionObject` - измерение, а не текст справки: страница свойства
называет тип `IModelObject`, но не перечисляет допустимые объекты. Продукт обязан либо принимать ссылку
на ось (вспомогательная геометрия уже адресуется существующим инструментом), либо честно отказывать
`DISMANTLE_DIRECTION_UNSUPPORTED`, если клиент дал не ось.
