# Master geometry - решения и измерения

Модуль: `kompas_copy_geometry`, `kompas_list_copies_geometry`, `kompas_synchronise_copy` (наряд
`OMEGA_G8_MASTER_GEOMETRY`). Здесь - история и отвергнутое, вынесенное из кода; действующие правила
остаются в коде под метками `DOC:` / `MEASURED:` / `INVARIANT:`.

## <a id="copy-geometry-route"></a>Маршрут «Копия геометрии»: адрес объекта и `Update()` (21.10.2026)

**Что было.** Наряд §1 ставил главным риском адрес объекта чужого документа: принимает ли
`ICopyGeometry.AddInitialObjectsFromExternalDocument` объект источника и как его назвать устойчиво.
Проба `tools/KompasMcp.Api7Probe --copy-geometry` шла по маршруту `Add()` → свойства →
`AddInitialObjectsFromExternalDocument` → `RebuildDocument` → чтение.

**Что измерено.** Адрес есть и принимается: тело источника, взятое документированным путём
`ksPart.BodyCollection()` → `refresh()` → `GetByIndex(0)` → `TransferInterface(…, ksAPI7Dual)`, отвечает
`IsSuitableObject = TRUE`, вызов возвращает `TRUE`, `IsInitialObject` → `TRUE`, а `DocumentFileName`
получает путь сохранённого `.m3d`. Тело из `ksPart.GetMainBody()` тем же маршрутом отвечает
`IsSuitableObject = FALSE` - это разные объекты, и адресуется именно элемент коллекции тел. Плоскость
XoY адресуется так же.

Но операции в модели не было: дерево приёмника содержало только «Начало координат», коллекция
`CopiesGeometry` после принятого вызова отвечала `Count = 0`, `CollectionsGeometry.Count` = 0,
`OpenDocument` и `GetExternalLocalCooordinateSystem` → `null`.

**Что решено.** Недостающим документированным шагом был `IModelObject.Update()`
(`sdk-docs/imodelobject_update.html`: «Метод Update необходимо вызвать для объекта, свойства которого
были изменены … чтобы эти изменения вступили в силу»). `ICopyGeometry` наследует `IModelObject`
(`icopygeometry.html`, раздел «Иерархия»: `IDispatch` → `IKompasAPIObject` → `IModelObject` →
`ICopyGeometry`), поэтому вызов делается на самой операции. После него дерево приёмника получает строку
«Копирование:1», тел 1, объём 80 000 мм³, `CopiesGeometry.Count` = 1, `IsInitialObject` = TRUE.

**Отвергнуто.** Гипотеза попытки 1 «принятый вызов забирает операцию в `CollectionsGeometry`»
опровергнута: `CollectionsGeometry.Count` = 0 и после вызова, а `ICollectionGeometry.Geometry` с
`ByCollectionGeometry = TRUE` на дерево не влияет.

## <a id="associativity"></a>Ассоциативность: `Synhronise()` переносит изменение источника (21.10.2026)

**Что измерено.** Источник - пластина 100x80x10; толщина признака изменена на 25 мм
(`SetSideParam` + `ksEntity.Update()`); приёмник после `WatchForSourceChange = FALSE` и
`Synhronise()` = TRUE даёт объём 200 000 мм³ против 80 000 до синхронизации (ожидание 100x80x25, объём
совпал без расхождения). Это и есть требуемое нарядом доказательство ассоциативности: без
синхронизации приёмник не менялся.

**Что решено.** Подтверждение успеха копии - чтение дерева и объёма приёмника, а не `BOOL` вызова: в
той же пробе `AddInitialObjectsFromExternalDocument` отвечал `TRUE` для признака выдавливания, а
`IsInitialObject` для него был `FALSE`.

## <a id="probe-two-arms"></a>Два плеча пробы: источник сеанса и источник с диска (21.10.2026)

**Что было.** Шаг «источник открыт с диска» в попытке 1 ничего не измерял: `Open()` файла, который
сеанс уже держит открытым, отвечает `FALSE`, и проба молча продолжала работать с документом, созданным
`Document3D()`. Тот же дефект был у шага «сохранение → переоткрытие приёмника».

**Что решено.** Перед `Open()` документ закрывается (`ksDocument3D.close()`), и только потом файл
открывается. Оба плеча вынесены в зонд: `--copy-geometry` (источник - документ сеанса, ассоциативность
измеряется) и `--copy-geometry-disk-source` (источник - файл, открытый с диска). На втором плече копия
создаётся так же (дерево «Копирование:1», объём 80 000), но признак выдавливания переоткрытого
документа через `ReadFeatures` не находится (`Entity` = null), поэтому ассоциативность там не
измеряется - её строку закрывает группа приёмки, где источник правится инструментами Хоста.

**LIMIT:** адресация опирается на коллекцию тел источника; произвольный объект источника (эскиз, ось)
документированного адреса через этот маршрут не получил.

## <a id="source-gone"></a>Источник недоступен: `Synhronise()` не отказывает (21.10.2026)

**Что измерено.** Приёмник с созданной копией (объём 200 000 мм³), документ-источник закрыт, файл
источника удалён с диска. `Synhronise()` отвечает `TRUE`, после `RebuildDocument` в приёмнике по-прежнему
одно тело и тот же объём 200 000 мм³, дерево - «Начало координат», «Копирование:1»,
`DocumentFileName` - прежний путь (файла по нему уже нет).

**Что решено.** `BOOL` от `Synhronise()` не различает «синхронизировано» и «источник недоступен», а
геометрия приёмника переживает пропажу источника. Значит отказ «источник не читается» решает Хост по
пути (`source_path` в читаемых корнях, файл существует и открывается), а не продукт. Строка приёмки
«несуществующий файл» проверяет именно ответ Хоста, а не `Synhronise`.

**LIMIT:** что произойдёт, если источник изменится при недоступном файле и файл потом вернётся, не
измерялось.

## <a id="tools"></a>Инструменты копии геометрии: форма, отказы и уровень подтверждения (21.10.2026)

**Что решено по форме.** Три инструмента и три команды Worker: `kompas_copy_geometry`
(`master.copy_geometry`), `kompas_list_copies_geometry` (`master.list_copies_geometry`),
`kompas_synchronise_copy` (`master.synchronise_copy`). Создание и синхронизация - мутации с
`expected_revision` и бюджетом 240 000 мс (правка модели через API7 медленнее чтения). Номер операции -
ПОЗИЦИЯ в `ICopiesGeometry`, а не адрес: он сдвигается после создания и удаления, поэтому строка чтения
его и выдаёт, а мутации его принимают. `object_kind` знает только `body` и `plane_xoy` - это то, что
измерено адресуемым; других значений нет, а не «пока нет».

**Отказы взяты существующими кодами.** Несуществующий файл источника - `DOCUMENT_NOT_FOUND`
(`RequireSourceFile`), путь вне корней - `PATH_NOT_ALLOWED` (политика Хоста, поле `source_path` уже в
её списке), источник без адресуемого объекта - `NO_BODY`, непринятая операция - `GEOMETRY_FAILED` с
`partial_effects: true` и числами в `details`, устаревшая ревизия - `REVISION_CONFLICT`. Новый код не
заводился: клиенту не нужно различать исходы, которые эти коды уже называют.

**Уровень подтверждения разный и назван честно.** Создание отвечает `geometry_checked`: тела и объём
приёмника прочитаны до и после, операция есть в коллекции. Синхронизация отвечает `call_returned`:
`Synhronise()` не различает «синхронизировано» и «источник недоступен» (`#source-gone`), ожидаемого
объёма инструмент не знает, поэтому объём до и после возвращается, а суждение остаётся клиенту.
Источник синхронизации проверяется ДО вызова продукта - файл по записанному `DocumentFileName` должен
существовать.

**LIMIT:** автоматического обновления по `WatchForSourceChange` нет - справка его не обещает, признак
только читается и пишется; удаление операции в профиль не входит (у `ICopyGeometry` документирован
`Destroy()` массива, отдельного инструмента нет). Обе строки приёмки помечены UNKNOWN с причиной.
