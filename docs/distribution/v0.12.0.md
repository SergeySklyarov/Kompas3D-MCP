# KompasMCP 0.12.0 - состав изделия и спецификация

Выпуск для КОМПАС-3D v24 x64. К 0.11.0 добавлен состав изделия: сводная ведомость сборки с деревом и
количествами, выгрузка ведомости в CSV и JSON, свойства компонента по ссылке и чтение родной
спецификации модели. Попутно исправлен адрес компонента: он указывает на сам компонент, а не на запись
с тем же именем файла, и мутация больше не может попасть в чужой экземпляр.

## Файлы выпуска

| Файл | Что это |
|---|---|
| `KompasMCP-v0.12.0-win-x64.zip` | готовый сервер: Host, Worker, зависимости, схемы, шаблон конфигурации, `INSTALL.md`, установщик, лицензии |
| `SHA256SUMS.txt` | SHA-256 архива, манифеста и установщика |

| `Install-KompasMcp.ps1` | установщик: зависимости, контрольная сумма, распаковка, конфигурация, самопроверка |

Архив «Source code» на странице выпуска GitHub создаёт сам: это исходники, готового сервера в нём
нет.

## Требования

- Windows x64.
- КОМПАС-3D v24 x64 (проверено на 24.0.0.2799), установленный, лицензированный и зарегистрированный
  для COM у текущего пользователя. Его DLL и interop в пакет не входят.
- .NET 10 Runtime x64 (`Microsoft.NETCore.App 10.x`); подходит и .NET 10 Desktop Runtime x64.
  .NET SDK не нужен.

Один инструмент требует КОМПАС не ниже v23: `kompas_measure_gap` (зазор между компонентами) опирается
на документированный `IPart7.Measurement3D`, который справка объявляет с версии 23. Ниже порога
инструмент отказывает `CAPABILITY_UNAVAILABLE` с названной версией и порогом.

Установка и подключение: [Codex](../operator-guide/codex-setup.md),
[Claude](../operator-guide/claude-setup.md), [другой клиент](../operator-guide/install.md).

## Что сломано для клиента

Обязательных полей не прибавилось, удалённых и переименованных операций нет, схемы существующих
операций не изменились. Одно изменение касается значений, которые клиент получает и передаёт обратно.

### Адрес компонента в сборке означает другой экземпляр

**Что было.** Адрес компонента считался счётчиком по номеру записи в перечислении компонентов, а
адресом служит номер элемента в плоской коллекции сборки. Экземпляр, исключённый из расчёта, в
перечисление не попадает, поэтому все следующие адреса съезжали на единицу: адрес указывал на
исключённый экземпляр или на компонент из другого файла с тем же именем. Сверка при этом сравнивала
только имя файла и подтверждала чужой экземпляр.

**Что стало.** Адрес находится сопоставлением записи с элементом коллекции по полному пути файла и
размещению, а не счётчиком; сверка сравнивает полный путь. Если сопоставить не с чем - сборка
изменилась под ссылкой (экземпляр удалён, файл-источник заменён, размещение сдвинуто), файл-источник
записи не прочитан или размещение не совпало, - запись получает отказ `STALE_REFERENCE` без адреса, а
не чужой номер. Два взаимозаменяемых экземпляра одного файла в одном размещении адрес получают: их
различает порядок, в котором их выдаёт перечисление. Изменение касается
`kompas_list_components`, `kompas_delete_component`, `kompas_replace_component`,
`kompas_set_component_placement`, `kompas_get_component_properties` и `kompas_get_bom`.

**Что делать клиенту.** Не хранить адрес между вызовами: адрес - это номер экземпляра в текущем
состоянии сборки, и после вставки, удаления или исключения экземпляра он может означать другой
компонент. Брать адрес из `kompas_list_components` непосредственно перед вызовом, который его
принимает, и сверять с ним `file` и `name`.

## Как обновиться

Запустить установщик нового выпуска без `-Tag` - он скачивает пакет, проверяет контрольную сумму и
переключает постоянную точку `<InstallRoot>\current` на новую версию. Запись клиента при этом не
меняется: она указывает на `current`, поэтому после перезапуска сервера в клиенте работает новая
версия, а строку `command` править не нужно. Если запуск через `current` отказывает, установщик
называет текст исключения и рабочий абсолютный путь
`<InstallRoot>\versions\v0.12.0\KompasMcp.Host.exe`.

**Сообщение о новой версии.** Ответ `kompas_health` несёт поле `update`; проверка идёт в фоне не чаще
раза в сутки, выключается ключом `update_check: false` или переменной `KOMPAS_MCP_UPDATE_CHECK=0`.
Сервер только сообщает: он ничего не скачивает и не устанавливает.

## Что добавлено

### Сводная ведомость состава сборки

`kompas_get_bom` читает состав сборки документированным маршрутом и отдаёт строки ведомости: полный
путь файла, имя, обозначение, материал, признаки `hidden`, `excluded`, `standard` и число экземпляров,
плюс итоги `instances_walked`, `rows`, `skipped`. Группировка идёт по ПОЛНОМУ пути файла, а не по
имени: два разных файла с одинаковым именем остаются двумя строками. Вложенные сборки читаются
рекурсией по файлам компонентов; документ обхода закрывается в любом исходе и в сеансе не остаётся.
Цикл ссылок и ненаходимый файл дают отказ с путём, а не молчаливо неполную ведомость.

### Выгрузка ведомости

`kompas_export_bom` пишет те же строки в CSV или JSON по названному пути. Скрытые и исключённые
экземпляры по умолчанию пропускаются и считаются в `skipped`; инвариант ответа
`строки + skipped = instances_walked` проверяется. Существующий файл без `overwrite` отвергается
(`PATH_NOT_ALLOWED`, до построения строк - файл и модель не тронуты), с `overwrite=true` выгрузка
перезаписывает его; путь вне разрешённых корней отвергается тоже.

### Свойства компонента по ссылке

`kompas_get_component_properties` читает восемь документированных свойств компонента по ссылке из
`kompas_list_components`: файл, имя, обозначение, материал, скрытость, исключение из расчёта, признак
стандартного изделия и многотельность. Ничего не пишется; свойства читаются у того экземпляра, на
который указывает адрес, включая второй экземпляр того же файла.

### Родная спецификация модели

`kompas_get_specification` отдаёт строки объектов РОДНОЙ спецификации модели: раздел и его номер,
позицию, обозначение, наименование, количество, число и примечания. С деревом сборки строки не
смешиваются и ничего не досчитывается. У модели без спецификации приходит пустой список с заметкой, а
не отказ.

## Исправлено

### Сравнение объёма больше не выдаёт провал без ожидания

Без `expected_volume_mm3` правка признака публиковала проверку `passed=false` с
`expected="не задано"` и в `unverified_aspects` - `volume_not_as_expected`. Теперь проверка сравнения
появляется ТОЛЬКО при заданном ожидании: `checks` становится короче на одну запись, а отсутствие
ожидания называет один `expected_volume_not_supplied`. Расхождение с заданным ожиданием по-прежнему
публикуется проваленной проверкой и предупреждением. Если клиент считал записи `checks` по числу, это
изменение формы ответа; поля и их имена не менялись.

### Ссылка из создания признака пригодна сразу

`kompas_loft` (и `kompas_sweep`) возвращали ссылку, которую следующий же `kompas_get_feature`
отвергал `STALE_REFERENCE`, а её `revision` была на единицу меньше ревизии результата. Ссылка теперь
указывает на элемент дерева и несёт ревизию после создания.

### Число тел у приклеенного элемента по сечениям

Проверка `body_count_grew` у `kompas_loft` и `kompas_sweep` заменена на `body_count_kept`: у
приклеенного элемента число тел штатно не растёт, поэтому прежняя проверка сообщала провал при верном
результате. Клиенту, который искал `body_count_grew` по имени, следует читать `body_count_kept`.

### Обязательность `target_body_ref` у `kompas_extrude` опубликована

Поле описано как условно обязательное: без него отвергаются `operation=boss` и `operation=cut`
(`INVALID_ARGUMENT` до обращения к КОМПАС), для `operation=base` оно не нужно. Отказ не изменился;
изменилось только описание поля в схеме.

### Адрес компонента указывает на сам компонент

Разбор - в разделе «Что сломано для клиента». Починка затронула и `kompas_check_interference`:
вставленные экземпляры одного файла в одном размещении получали один и тот же адрес, и проверка
сравнивала тело с самим собой, отвечая «пересечения нет» при настоящем зазоре. Теперь адрес у каждого
экземпляра свой, и пересечения и зазоры считаются по разным телам.

### Пустой кадр снимка называется своим именем

Снимок модели может прийти пустым: файл записан, изображение одноцветное. Сервер теперь измеряет это
сам и называет признаком `blank_snapshot`; в отчёт строки приёмочного прогона идут оба снимка целиком
(вид, предыдущий вид, габарит, байты, контрольная сумма, число цветов) и порядок вызовов со временем.
Причина пустого кадра не установлена и названа ограничением.

### Шаги выпуска идут при политике исполнения `Restricted`

`scripts/publish.ps1` запускается документированным параметром `-ExecutionPolicy Bypass` у
`powershell.exe`: политика задаётся только текущей сессией и в файл конфигурации не пишется, политика
машины не меняется. Команда записана в шапке скрипта.

### Устаревшее подтверждение клиента снимается шагом выпуска

Если в хранилище подтверждений клиента лежат два подтверждения одного имени, проверка называет
устаревший ключ с временем выдачи, действующую запись и шаг чистки. Живое хранилище продукт не
правит: снятие устаревших подтверждений - шаг выпуска, Trust остаётся за владельцем машины.

### Приборы берут только проверенный вход

Аудит соответствия API больше не выбирает отчёт приёмки сам: путь обязателен, несуществующий путь -
отказ с путём, прочитанный отчёт печатается первой строкой и попадает в отчёт. У строки «конец
сеанса» клиентской приёмки один прибор и одна схема базовой линии; отсутствующее поле называется в
`missing_fields`, а не заполняется пустым значением.

## Изменено

- **Описания инструментов и `docs/TOOLS.md`** получили записи новых операций; путь вызова (`direct`
  или `run`) у новых операций - `run`.
- **Границы состава изделия названы в описаниях.** `kompas_get_bom` и `kompas_export_bom` говорят,
  что скрытый и исключённый экземпляры остаются в коллекции сборки, а пропуск считается в `skipped`;
  `kompas_get_specification` называет границу `.spw` и отсутствие записи спецификации.

## Известные ограничения

Перенесены из заметок 0.11.0 и сверены с деревом выпуска. Ниже добавлены ограничения, названные в
этом выпуске.

- **Спецификация: только чтение (новое).** Запись объектов спецификации в выпуск не входит: строки
  читаются, но не создаются и не правятся.
- **Спецификация: `.spw` не читается (новое).** Единственный документированный вход адресует АКТИВНЫЙ
  документ сеанса, а не названный `document_id`, поэтому спецификация отдельного файла `.spw` вне
  объёма; читается спецификация модели.
- **Спецификация: не все поля отдаются (новое).** Уникальный номер, тип объекта, состояние, масса и
  материал строки не входят в контракт: документированного маршрута чтения для них не найдено.
- **Состав: исключённый экземпляр виден только по счётчику (новое).** Исключённый из расчёта
  экземпляр не появляется в перечислении компонентов сборки, но остаётся в её коллекции, поэтому
  ведомость пропускает его и считает в `skipped`, а не показывает отдельной строкой.
- **Состав: рекурсия открывает файлы компонентов (новое).** Вложенная сборка читается открытием её
  файла; недоступный файл и цикл ссылок дают отказ с путём, а не частичную ведомость.
- **Адрес компонента привязан к состоянию сборки (новое).** Адрес - номер экземпляра в текущей
  сборке. Если сборка изменилась под ссылкой (экземпляр удалён, файл-источник заменён, размещение
  сдвинуто) или сопоставить запись с экземпляром нечем, вызов отвергается `STALE_REFERENCE`, а не
  читает чужой компонент. Два экземпляра одного файла в одном размещении - не отказ: они
  взаимозаменяемы, и адрес у каждого свой.
- **Пустой кадр снимка модели (новое).** Снимок может прийти одноцветным; сервер называет это
  признаком `blank_snapshot`, причина не установлена. Тело при этом построено и читается.
- **Листовое тело: удаления нет.** Инструмента удаления листового тела нет; удаляют признак или тело
  существующими средствами КОМПАС.
- **Листовое тело: одна таблица сгибов не задаётся.** Способ развёртки и его поле правятся, а
  таблицы сгибов в контракте нет.
- **Листовое тело: сгиб по одному ребру за вызов.** Набор рёбер и сгиб по эскизу не входят в выпуск.
- **Выгрузка развёртки: имя проекции названо литералом.** Имя проекции развёртки задаётся тем
  значением, которое даёт сама установка КОМПАС; чтения имени из модели в контракте нет.
- **Выгрузка развёртки: закрытие временного чертежа не подтверждается.** Документ не остаётся в
  сеансе, но возврат закрытия не подтверждён и назван в `unverified_aspects`.
- **Удаление механической передачи не поддержано.** Создание, чтение и правка отношения и направлений
  работают; удаление передачи отказывает, вторая передача на той же паре не создаётся.
- **Сечение сборки не строится при включённом разнесённом виде.** Выключить режим
  (`kompas_set_dismantle`, `mode=false`) и повторить.

- **Разнесённый ассоциативный вид чертежа не поддержан.**
- **Вид базового объекта резьбы при чтении не отдаётся.** Продукт определяет базовую грань по ребру,

  `CAPABILITY_UNAVAILABLE` с подсказкой удалить вид и построить заново.
- **Разрез строится только на чертеже и виден ассоциативным видом.**
- **Удаление вида разреза оставляет линию разреза.** Ответ говорит это прямо.
- **Форма стрелок и размыкание линии разреза подтверждены только снимком.**
- **Трасса мимо тела не даёт пустого вида.**
- **Снятие сервера клиентом без штатного завершения завершает собственный КОМПАС силой.**
- **Прилегание поверхности проверяется только для ПРЯМОГО ребра.**
- **ФЛАГ состояния эскиза может читаться как недоопределённый, ПАРАМЕТРИЧЕСКОЕ ПОВЕДЕНИЕ при этом

## Совместимость

Выпуск 0.12.0 - MINOR от 0.11.0. **Удалённых и переименованных операций нет, обязательных полей не
прибавилось, схемы существующих операций не изменились**; вызовы, которые работали в 0.11.0,
работают и здесь. Единственное изменение значений - адрес компонента (см. «Что сломано для клиента»).

Аддитивно: 4 операции (`kompas_get_bom`, `kompas_export_bom`, `kompas_get_component_properties`,
`kompas_get_specification`) и новый профиль приёмки `bom-minimal-v1`.

## Проверка выпуска

Приёмка идёт по файлам поставки, а не по дереву разработчика, и клиентская приёмка проводится рабочим
клиентом на той же поставке.

- **Девятнадцать профилей закрыты полностью:** 127 из 127 режимов, 76 из 76 зависимостей, вердикт
  `COMPLETE`, открытых режимов и зависимостей нет.
- **Функциональная приёмка на файлах поставки:** 168 файлов, 9,1 МБ, 14 инструментов, 118 операций,
  схемы 118 = репозиторий. Полный живой прогон - **1916 PASS / 6 NAMED / 3 UNKNOWN / 0 FAIL**
  (1925 строк, 25 групп); дополнительный прогон «подавить -> снять» (20 повторов на двух
  постановках) - **41 PASS / 1 NAMED / 0 FAIL**. Состав строк сверен с зачётным прогоном цикла
  поимённо: отсутствующих строк 0.
- **Клиентская приёмка** рабочим MCP-клиентом на той же поставке: **30 строк, 29 выполнено и
  соответствует ожиданию, расхождений 0**; одна строка («конец сеанса») клиентом не выполняется по
  определению. Паспорт поставки - PASS по всем уровням, `fully_ready = true`.
- **Модульные тесты** проходят полностью, отказов нет.
- **Стражи:** ссылки на доказательства разрешаются; длинных и средних тире в публикуемом тексте нет;
  блок инструментов в `docs/TOOLS.md` совпадает с реестром.
