# Конфигурация и подключение к MCP-клиенту

## Файл конфигурации

Формат — JSON, пути абсолютные. Пример: `config/kompas-mcp.example.json`.
Ключи (см. `HostOptions.Load`):

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `read_only_roots` | модели, которые сервер читает, но не пишет | пусто |
| `writable_roots` | песочницы для сохранений и черновиков | пусто |
| `export_roots` | куда кладутся экспорты и пакеты | пусто |
| `allow_unc_paths` | разрешить `\\server\share` | `false` |
| `require_read_only_model_roots` | сообщить в stderr при старте, если корень записи лежит внутри read-only | `true` |
| `worker_path` | явный путь к `KompasMcp.Worker.exe` | рядом с Host |
| `log_path`, `worker_log_path`, `journal_path` | JSONL-файлы наблюдений | в системном temp |
| `queue_capacity` | глубина очереди CAD-команд | 64 |
| `sync_budget_ms` | сколько ждать синхронно, дальше — polling | 10000 |
| `operation_budget_ms` | бюджет одной операции на Worker | 120000 |

Переменные окружения перекрывают файл: `KOMPAS_MCP_CONFIG`,
`KOMPAS_MCP_READONLY_ROOTS`, `KOMPAS_MCP_WRITABLE_ROOTS`, `KOMPAS_MCP_EXPORT_ROOTS`
(разделитель — `;`), `KOMPAS_MCP_WORKER_PATH`, `KOMPAS_MCP_INTEROP_DIR`.

## Почему roots обязательны, а не «разрешить всё»

Сервер пишет в модель по запросу из LLM-агента. Граница между «рабочая папка заказчика» и
«песочница» не может выводиться из имени файла: `StartsWith` без проверки разделителя пропускает
`D:\workspace` вместо `D:\work`, а `Path.GetFullPath` не раскрывает junction. Реализация —
`Domain/Paths/PathPolicy`, проверена тестами `PathPolicyTests`.

Практическое следствие для исходников EH70: их держат в `read_only_roots`.
Попытка сохранить туда даёт `PATH_NOT_ALLOWED` **до** любого обращения в КОМПАС.

## Подключение в MCP-клиент

Windows-клиент запускает Host как `stdio`-сервер:

```json
{
  "mcpServers": {
    "kompas": {
      "command": "<каталог-поставки>\\KompasMcp.Host.exe",
      "args": ["--config", "<корень-репозитория>\\config\\kompas-mcp.local.json"],
      "timeout": 600000
    }
  }
}
```

`command` — **абсолютный** путь к Host из поставки, а не к отладочной сборке: подставьте свой каталог
поставки. Локальный конфиг `config/kompas-mcp.local.json` **в репозитории не лежит** — он создаётся
из шаблона `config/kompas-mcp.example.json`, потому что содержит пути этой машины. Шаблон публикуется,
значения путей в нём условные по построению и требуют замены.

**Пометка 22.09.2026.** Прежняя редакция этого примера содержала абсолютные пути этой машины, включая
каталог сборки `artifacts/publish-b2-20260918`, которого в публикуемом репозитории нет, и ссылку на
`scripts/localconfig.py` — прибор разработки, тоже не публикуемый. Пример заменён на условные пути:
на чужой машине прежний пример не сработал бы вовсе.

**Поправка 23.09.2026.** Второе утверждение той пометки перестало быть верным: решением заказчика
каталог `scripts/` **публикуется целиком**, и `scripts/localconfig.py` в наборе **есть**. Основание
публикации измерено: без приборов читатель публичного репозитория не может воспроизвести ни одну из
заявленных проверок. Причина замены примера от этого не изменилась и остаётся в силе — абсолютные
пути этой машины и ссылка на конкретную поставку в публичном примере недопустимы. Сама пометка не
переписана: она верно описывает редакцию на 22.09.2026.

Важные детали, которые экономят время:

* **`command` — абсолютный путь к Host из поставки**, а не к отладочной сборке. Проверить, что
  клиент запустил именно поставку, можно по `worker_path` и хешам в шапке отчёта приёмки
  (`scripts/mcp-smoke.py` пишет их в поле `context`).
* **`KOMPAS_MCP_WORKER_PATH` не задавайте.** Переменная перекрывает `worker_path` из конфига;
  заданная «на всякий случай», она уводит новый Host на чужой (обычно отладочный) Worker, и
  приёмка начинает мерить не ту поставку. Host сам берёт `KompasMcp.Worker.exe` из своего каталога.
* **stdout Host — только протокол MCP.** Диагностика идёт в stderr и в `log_path`; если клиент
  показывает «мусор в протоколе», виноват не сервер, а перенаправление.
* **Worker не запускают вручную.** Host поднимает его сам с уникальным именем канала; запущенный
  руками Worker без аргумента `--pipe` просто завершится.
* **Клиент не должен сам выбирать «активный документ»** — его и нет: `Document3D()` это фабрика
  (P0.5). Порядок: `kompas_get_context` → взять `document_id` и `revision` → дальше по ним.
* **Холодный запуск КОМПАС ~3–9 с.** Первый `kompas_connect` может не уложиться в дефолтный
  таймаут клиента; увеличьте его на стороне клиента или передайте `timeout_ms`.
* **`timeout` на стороне клиента** должен покрывать бюджет операции (`operation_budget_ms`,
  по умолчанию 120 с; в локальном конфиге проекта — 240 с). Если операция всё же не уложилась в
  `sync_budget_ms`, сервер вернёт `status: running` и попросит повторить тот же вызов с тем же
  `operation_id` — это и есть опрос.

## Проверка, что сервер жив, не трогая модель

```
kompas_health {detail: "minimal"}
kompas_capabilities {}
```

`health` отвечает даже когда CAD-канал занят или КОМПАС не подключён: Host и Worker — разные
процессы, и control-канал Worker'а не ставится в очередь к STA-потоку.
