# Откат, checkpoint и внешние ссылки

## Модель отказа

Сервер не «отменяет» изменения КОМПАС: транзакций уровня документа API5 не предоставляет, а
`OUTCOME_UNKNOWN` означает в том числе «мы не знаем, что уже применилось». Поэтому откат — это
**восстановление из копии**, а не отмена операции. Порядок обязан быть таким:

1. перед серией правок — checkpoint (`.kompas-checkpoint/` рядом с моделью);
2. после каждой мутации — перечитывание контекста (`kompas_get_context`), а не доверие bool;
3. при сбое — сравнение с checkpoint и осознанный откат, а не повтор упавшей команды.

## Что должно быть в checkpoint

Минимальный достаточный набор для `.a3d`:

* сам файл сборки;
* **все** parts, на которые она ссылается, с сохранением относительных путей — иначе сборка
  откроется «без компонентов» и это будет выглядеть как успех;
* параметры сортиментов/COVER (EH70: `Parameters.xml`), если сборка от них зависит;
* хеши и размеры (SHA256 каждого файла), чтобы откат был проверяемым, а не «надеюсь, скопировалось».

Проверка отката — не «файл вернулся», а: сборка открывается, `component_count` совпадает, у
каждой детали совпадают габарит и число тел с записанными в checkpoint. Пока это не реализовано
как инструмент, проверка делается вручную по `kompas_get_context` / `kompas_list_bodies`.

## Внешние ссылки

Два режима, и они не взаимозаменяемы (spec 1.9):

| Режим | Что происходит | Когда |
|---|---|---|
| `copy` | зависимости копируются в песочницу, сборка указывает на копии | эксперимент, который может испортить модель |
| `read_only` | зависимости остаются общими | инспекция, измерения, сверка спецификации |

Создание сборки из исходников EH70 в режиме `read_only` **обязано** быть невозможен: любое
сохранение затронуло бы общие parts. Поэтому `kompas_save_document` в песочницу с общими
зависимостями обязан сначала доказать, что ни один существующий файл не был перезаписан
(сравнение хешей источника).

## Правка чужой вставки

Единственный разрешённый путь: copy-песочница → открыть копию в **своей** сессии → изменить →
сохранить в песочницу → показать diff и дождаться подтверждения. Прямой мутации исходной детали
и записи в общий путь сервер не делает ни при каких аргументах — это ограничение контракта, а не
настройка безопасности.

## Если что-то пошло не так

1. повтор того же вызова с тем же `operation_id` — журнал Host вернёт записанный исход
   (`succeeded`/`failed`/`cancelled`/`outcome_unknown`), а незавершённая операция ответит
   `running`. Отдельного инструмента состояния операции в каталоге нет.
2. `OUTCOME_UNKNOWN` → не повторять мутацию; сверить модель с checkpoint.
3. `DOCUMENT_DIRTY` → решить явно: `save`, `discard` или оставить как есть. Молча терять
   несохранённое изменение сервер отказывается по умолчанию.
4. Подозрение на зависший КОМПАС → `kompas_health {detail:"diagnostic"}`: живой Host и живой
   Worker при занятом STA-канале означают «КОМПАС думает», а не «сервер упал». Завершать процесс
   КОМПАС принудительно — действие пользователя, не сервера.
